How it grows

One branch name.
Every repo. One command.

Set up the group once. From then on, any branch is a single gv call — and everything else is already done.

Set up once

Name a group of repos: fullstack = frontend + backend. That's the whole config — and a single repo needs none.

Then, one command

gv fullstack fix-auth — a worktree in every repo on the same branch, deps installed, each repo's .claude/skills and .cursor merged so one agent sees them all, in a fresh tmux session with your agent already running. Any repo fails, they all roll back.

The canopy

Small tool. Deep roots.

Everything you need to run several branches — and several agents — in parallel without tripping over yourself.

Multi-repo workspaces

Group projects together and one command cuts worktrees across all of them — every repo on the same branch name, ready at once.

One agent, every repo

grove copies each repo's .claude/skills and .cursor into the workspace root, so a single agent at the root sees the skills and rules from every repo it's working across.

Agents resume on reopen

A worktree outlives its tmux session. Reopen a workspace and grove brings your agent back with --continue — it picks up the conversation right where you left it.

Lives in your shell

No app, no binary, no daemon — grove is one Zsh function you source. It works over SSH and on any box, and each workspace is its own tmux session, auto-named so a wall of tabs stays legible.

Interactive TUI

Type gv with no args for an fzf dashboard of every workspace — with a live branch tree and PR status (via gh) in the preview pane.

Rollback on failure

If any worktree in the set fails to create, grove tears the whole thing back down — no half-planted workspace left behind.

The part you keep re-scripting

Worktrees are easy. Worktrees across three repos aren't.

Cutting one worktree is a one-liner. Cutting them across every repo a task touches — same branch, deps installed, agent config in place, a tmux session named — is the bit you rebuild by hand every time.

by hand per repo, every time
  1. git fetch and figure out if the branch already exists on a remote
  2. track it if it does, create it if it doesn't
  3. git worktree add in the right place
  4. rebuild the workspace directory layout
  5. reinstall dependencies
  6. symlink or copy each repo's agent config
  7. start and name a tmux session
  8. …then remember to prune all of it later
with grove once 
❯ gv fullstack fix-auth

Fetch, branch resolution, a worktree in every repo, deps, merged agent config, tmux, your agent — all of it. Clean up with gv --rm, or gv --kms from inside.

Field guide

The whole vocabulary.

One verb — gv — does it all.

gv --help
everyday
gv
Open the interactive TUI dashboard
gv <workspace> <name>
Create or attach to a workspace instance
gv <workspace> <name> <cmd>
Run a command in the workspace (no tmux)
gv --ls
Show the branch tree for the current workspace
gv --list
List every workspace and instance
tending
gv --no-tmux <workspace> <name>
Create it, print its dir, skip tmux (for scripts & agents)
gv --rm [--force] <ws> <name>
Remove an instance (--force if it's dirty)
gv --kms [--force]
Remove the current workspace, from inside it
gv --home
cd to your projects directory
gv --update
Pull the latest grove
gv --help
Show the full usage guide
